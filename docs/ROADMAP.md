# 여행 가이드 블로그 개발 로드맵

## 📋 개발 단계 개요

이 로드맵은 Notion 기반 여행 가이드 블로그를 체계적으로 구축하기 위한 개발 순서를 정의합니다.  
각 단계는 이전 단계의 기반 위에서 진행되며, 순서를 따를 때 효율적인 개발이 가능합니다.

---

## 1단계: 프로젝트 초기 설정 (골격 구축)

### 📌 작업 내용

1. **개발 환경 구성**
   - Node.js 및 npm 설치 확인
   - Next.js 15 프로젝트 초기화
   - TypeScript, Tailwind CSS, shadcn/ui 설치 및 구성

2. **Notion API 연동 준비**
   - Notion 계정에서 데이터베이스 생성
   - API 통합(Integration) 생성 및 시크릿 키 발급
   - 데이터베이스 권한 설정 (통합에 대한 접근 허용)

3. **환경 변수 설정**
   - `.env.local` 파일 생성
   - `NOTION_API_KEY`, `NOTION_DATABASE_ID` 설정

4. **프로젝트 구조 구성**
   - 디렉토리 구조 설정 (`app/`, `components/`, `lib/`, `public/`)
   - 기본 레이아웃 컴포넌트 생성
   - 헤더, 푸터, 네비게이션 기초 구현

5. **테스트 데이터 준비**
   - Notion 데이터베이스에 샘플 글 3개 이상 작성
   - 카테고리 최소 3개 설정 (아시아, 유럽, 남미 등)

### 🎯 왜 이 순서인가?

- **기반 없이 개발 불가**: 개발 환경과 API 연동이 없으면 다른 모든 작업이 불가능합니다.
- **조기 데이터 준비**: 테스트하며 개발하기 위해 초기에 샘플 데이터가 필요합니다.
- **환경 일관성**: 팀 전체가 동일한 환경에서 작업할 수 있도록 설정해야 합니다.

### ⏱️ 예상 소요 시간

- **2-3일** (경험 있는 개발자: 1-2일)

### ✅ 완료 기준

- [ ] Next.js 프로젝트 정상 실행 확인
- [ ] Notion API 키가 정상 동작하는지 테스트
- [ ] 기본 레이아웃이 모든 페이지에 적용됨
- [ ] `.env.local`이 git ignore 처리됨
- [ ] Notion 데이터베이스에 테스트 데이터 최소 3개 입력

## 2단계: 공통 모듈/컴포넌트 개발

### 📌 작업 내용

1. **Notion API 클라이언트 구축**
   - `@notionhq/client` 설치
   - API 호출 함수 작성 (`lib/notion.ts`)
   - 타입 정의 (`types/notion.ts`)
   - 데이터 캐싱 로직 구현 (ISR 활용)

2. **공통 UI 컴포넌트 개발**
   - 글 카드 컴포넌트 (`components/PostCard.tsx`)
   - 페이지네이션 컴포넌트 (`components/Pagination.tsx`)
   - 검색 바 컴포넌트 (`components/SearchBar.tsx`)
   - 태그 표시 컴포넌트 (`components/TagBadge.tsx`)

3. **유틸리티 함수 작성**
   - 날짜 포맷팅 함수
   - 슬러그 생성 함수
   - 텍스트 요약 함수
   - 카테고리/태그 필터링 함수

4. **스타일 시스템 구성**
   - Tailwind CSS 커스터마이징 (`tailwind.config.ts`)
   - 색상, 폰트, 간격 등 디자인 토큰 정의
   - 반응형 디자인 기준점 설정

5. **Notion 블록 렌더러 개발**
   - 텍스트, 제목, 리스트 등 기본 블록 렌더링
   - 이미지, 코드 블록 등 복합 블록 지원
   - 안전한 HTML 렌더링 (XSS 방지)

### 🎯 왜 이 순서인가?

- **재사용성**: 공통 컴포넌트와 함수를 먼저 구축하면 다음 단계에서 중복 작업 없음
- **일관성**: 모든 페이지에서 동일한 UI/UX 유지
- **효율성**: API 호출과 캐싱 로직을 중앙화하면 관리와 수정이 용이

### ⏱️ 예상 소요 시간

- **5-7일** (경험 있는 개발자: 3-4일)

### ✅ 완료 기준

- [ ] Notion API 클라이언트가 데이터를 정상 조회
- [ ] 모든 공통 컴포넌트가 Storybook 또는 테스트 페이지에서 확인됨
- [ ] 유틸리티 함수의 단위 테스트 작성 완료
- [ ] Notion 블록의 주요 타입(텍스트, 이미지, 리스트) 렌더링 확인
- [ ] 캐싱이 정상 작동 확인 (같은 요청이 캐시에서 반환됨)

## 3단계: 핵심 기능 개발

### 📌 작업 내용

1. **홈 페이지 구현** (`/`)
   - 최근 발행된 글 목록 표시
   - 글 카드 레이아웃 구성 (썸네일, 제목, 카테고리, 발행일, 요약)
   - 페이지네이션 또는 "더보기" 버튼 구현
   - 글 로딩 상태(Skeleton) 표시

2. **글 상세 페이지 구현** (`/posts/[slug]`)
   - 동적 라우팅 설정 (`generateStaticParams`)
   - 글 제목, 메타데이터 표시 (카테고리, 발행일, 작성자)
   - Notion 콘텐츠 블록 렌더링
   - 이전/다음 글 네비게이션 추가

3. **카테고리 페이지 구현** (`/categories/[category]`)
   - 동적 카테고리 페이지 생성
   - 카테고리별 글 목록 필터링
   - 정렬 옵션 (최신순, 제목순)
   - 카테고리 메타데이터 표시 (글 개수, 설명)

4. **기본 검색 기능 구현**
   - 클라이언트 사이드 검색 (제목, 태그 기반)
   - 검색 결과 페이지 (`/search`)
   - 검색된 글의 개수 표시
   - 결과 없음 상태 처리

5. **메타데이터 및 SEO 기초**
   - 동적 메타 태그 생성 (각 페이지의 OG 태그)
   - 기본 robots.txt, sitemap.xml 생성
   - 구조화된 데이터 (Schema.org) 추가

### 🎯 왜 이 순서인가?

- **사용자 기반 기능**: 블로그 방문자가 직접 사용하는 기능들을 먼저 구현
- **핵심 가치 제공**: Notion에서 작성한 글을 블로그에서 보는 것이 주요 기능
- **테스트 용이**: 각 페이지를 독립적으로 테스트하고 피드백받기 가능

### ⏱️ 예상 소요 시간

- **7-10일** (경험 있는 개발자: 5-6일)

### ✅ 완료 기준

- [ ] 홈 페이지에서 최근 글 목록이 정상 표시됨
- [ ] 글 상세 페이지가 Notion 콘텐츠를 정확히 렌더링
- [ ] 모든 카테고리에 대해 페이지가 생성됨
- [ ] 검색으로 글을 찾을 수 있음
- [ ] 모바일에서 모든 페이지가 정상 표시됨
- [ ] Lighthouse 성능 점수 60점 이상 (초기 기준)

## 4단계: 추가 기능 개발

### 📌 작업 내용

1. **태그 기반 페이지** (`/tags/[tag]`)
   - 태그별 글 목록 표시
   - 동적 태그 페이지 생성
   - 태그 클라우드 또는 태그 목록 페이지

2. **사이드바 및 위젯**
   - 인기 카테고리 위젯
   - 최근 글 위젯
   - 태그 클라우드 위젯
   - 구독/연락처 위젯

3. **관련 글 추천**
   - 현재 글과 유사한 글 추천 알고리즘
   - 같은 카테고리 글 추천
   - 공통 태그 기반 추천

4. **고급 검색 기능**
   - 서버 사이드 검색 최적화
   - 검색 필터 (카테고리, 태그, 날짜 범위)
   - 검색어 자동완성

5. **피드 및 구독**
   - RSS/Atom 피드 생성
   - 카테고리별 피드
   - 피드 구독 버튼

6. **접근성 및 UX 개선**
   - ARIA 레이블 추가
   - 키보드 네비게이션 지원
   - 글자 크기 조절 옵션
   - 인쇄 버전 최적화

### 🎯 왜 이 순서인가?

- **부가 기능**: 핵심 기능이 완성된 후 사용성을 높이는 기능들 추가
- **지속 가능성**: 기본 기능이 안정적일 때 추가 기능 개발로 복잡성 증가
- **우선순위**: 사용자 피드백을 바탕으로 가장 필요한 기능부터 개발 가능

### ⏱️ 예상 소요 시간

- **5-7일** (경험 있는 개발자: 3-4일)

### ✅ 완료 기준

- [ ] 태그 페이지가 정상 작동
- [ ] 사이드바 위젯이 동적으로 데이터 로드
- [ ] 관련 글 추천이 의미 있는 결과 제시
- [ ] RSS 피드가 정상 생성 및 구독 가능
- [ ] 접근성 점수 85점 이상 (WAVE, Lighthouse)

## 5단계: 최적화 및 배포

### 📌 작업 내용

1. **성능 최적화**
   - 이미지 최적화 (Next.js Image, WebP 형식)
   - 번들 크기 분석 및 감소
   - CSS 최적화 (불필요한 클래스 제거)
   - Lazy loading 적용
   - 캐싱 전략 개선 (ISR 시간 조정, CDN 캐시)

2. **SEO 고도화**
   - 메타 디스크립션 최적화
   - 내부 링크 자동 생성
   - 구조화된 데이터 확장 (BreadcrumbList, Article 스키마)
   - Sitemap 자동 생성 개선
   - Open Graph 메타 태그 최적화

3. **분석 및 모니터링**
   - Google Analytics 통합
   - 에러 추적 설정 (Sentry 등)
   - 성능 모니터링 대시보드
   - 사용자 행동 분석

4. **보안 강화**
   - 환경 변수 보안 검토
   - API 요청 검증
   - CORS 및 CSP 설정
   - XSS, CSRF 방지 확인

5. **배포 및 CI/CD**
   - Vercel 또는 다른 호스팅 서비스 설정
   - 자동 배포 파이프라인 구성
   - 스테이징/프로덕션 환경 분리
   - 배포 전 자동 테스트 및 빌드

6. **문서화 및 유지보수**
   - 개발 문서 작성 (API 사용법, 컴포넌트 가이드)
   - 배포 가이드 작성
   - 문제 해결 가이드 (FAQ, 트러블슈팅)
   - 정기 유지보수 프로세스 정의

### 🎯 왜 이 순서인가?

- **사용자 경험**: 기능 구현 후 성능과 SEO로 사용자 만족도 향상
- **안정성**: 배포 전 최종 검증으로 프로덕션 이슈 예방
- **지속성**: 문서화와 모니터링으로 장기적인 운영 가능

### ⏱️ 예상 소요 시간

- **5-7일** (경험 있는 개발자: 3-4일)

### ✅ 완료 기준

- [ ] Lighthouse 성능 점수 90점 이상
- [ ] 페이지 로딩 시간(LCP) 3초 이내
- [ ] 모바일 SEO 점수 95점 이상
- [ ] 보안 점수 90점 이상
- [ ] 배포 프로세스 자동화 완료
- [ ] 모니터링 대시보드 정상 작동
- [ ] 배포 후 5단계별 체크리스트 통과
